# TypeAlike

OSS Windows-first Cotypist clone (https://cotypist.app/). System-wide inline autocomplete: ghost text at caret in any app, Tab accepts. Rust.

## Build
- Toolchain pinned `rust-toolchain.toml`; bump with `rust-version`.
- `cargo run` = app (default member `crates/typealike`, bin `TypeAlike`).
- Pre-commit = CI, all must pass: `cargo fmt --all --check`; `cargo clippy --workspace --all-targets` (`RUSTFLAGS=-D warnings`); `cargo test --workspace`; `cargo doc --workspace --no-deps`.
- GPU backends (Windows, opt-in): `cargo run --features vulkan,cuda`. The default build runs models on the CPU only. `vulkan` needs the Vulkan SDK (`VULKAN_SDK`). `cuda` needs the CUDA Toolkit and the CUDA DLLs on `PATH` at run time. Local build settings go in `.cargo/config.local.toml` (gitignored, loaded by `.cargo/config.toml`). Copy `.cargo/config.local.example.toml` to start. It sets the Ninja generator (the Visual Studio generator finds no CUDA toolset), `CUDACXX`, a short target folder (the Vulkan shader build goes past `MAX_PATH`), and `CMAKE_CUDA_ARCHITECTURES` for the local GPU only (much faster CUDA build). CMake configures llama.cpp only one time: after a change in `[env]` or a failed CMake step, run `cargo clean -p llama-cpp-sys-2`.
- Windows settings window: WinUI 3 through `windows-reactor`, a git dependency on windows-rs `master` at a fixed commit (the release 0.100.0 has no `AppProxy` and no public `App::run_with`). It is framework-dependent: running TypeAlike needs the Windows App Runtime 2 installed. The `self-contained` feature (`windows-reactor-setup` in `build.rs`) copies the runtime next to the program instead. It adds about 30 MB, and the Windows installers use it.
- Release: push a tag `vX.Y.Z` equal to the workspace version. `.github/workflows/release.yml` builds `TypeAlike-X.Y.Z-macos-arm64.dmg` (ad-hoc signature, no notarization) and two Windows installers, then makes a draft release. `-windows-x64-vulkan-setup.exe` has Vulkan. `-windows-x64-cuda-setup.exe` has Vulkan and CUDA with the cuBLAS DLLs. A manual run (`workflow_dispatch`) builds only the workflow artifacts. The scripts are in `packaging/`: `macos/build-dmg.sh` (app bundle from `Info.plist`, disk image), `windows/stage.ps1` (the files from the release folder, the Visual C++ runtime, cuBLAS) and `windows/TypeAlike.iss` (Inno Setup, current user only, `%LOCALAPPDATA%\Programs\TypeAlike`). `release.yml` pins MSVC 14.44, CUDA and the Vulkan SDK.
- Prompt eval: `cargo run --release -p typealike_llm --example prompt_eval -- MODEL.gguf crates/typealike_llm/examples/prompt_eval/cases/tuning.jsonl --baseline crates/typealike_llm/examples/prompt_eval/baselines/<model>.tuning.jsonl`. It prints the word scores, the median time, the cases that a change helped or harmed, and the mean log probability of the next word with its change. The log probability moves for small changes that leave the word scores the same. The median time is the time on the first key, when the model did not decode the prompt before. The warm time is the time after the model decoded the prompt when the input settled. It also prints the median tokens of a prompt, the time for each token, and the median time by the tokens of a prompt (1 to 128, 129 to 256, 257 to 512, 513 or more). `--notes TEXT` sets the notes about the writer, and `--name TEXT` the name of the writer. `--backend cpu|vulkan|cuda|metal` sets the backend (default: Metal on macOS, else the CPU). `--cpu-cores 4,6` gives the performance and efficiency cores, so that the CPU backend uses the threads of the app on Windows. `--batch TOKENS` sets the most tokens that one decode of a prompt takes on any backend (default: the batch of the backend, as in the app). Use it to measure another batch, and compare the median time of each prompt size. `--word-choice off|light|medium|strong` sets the word bias (default: off). `--word-bias off` turns off only the word bias, and keeps the next-word bias and the phrases. `--shared-history on|off` gives each app of a case the scope "All apps" (default) or "Only this app". It also prints the right and the wrong words that show, a table for a minimum probability of the first word, and a table for each cut of the tail. `--tail-cut off` turns off the cut of the app: use it to choose a cut. `--length very_short|short|medium|long|very_long` sets the suggestion length, with its token limit and its cut (default: medium). The CPU backend allows at most short, so measure a longer length on a GPU backend. `--replay word|character` also asks for a suggestion at the start of each word or after each character of `next` (default: off). The input always follows `next`, also after a wrong suggestion. The report then also gives the score of each replayed text. Use `character` for a change to the token healing, because each case has only one caret inside a word. `--sentence-stop on|off` stops each suggestion at the end of a sentence (default: on, as in the app). `--typo-rule on|off` sets the rule for typos (default: on, as in the app). The report then gives a table for each cut of the typed letters: the typo cases that it catches and the other cases that it hides. Run it with `--typo-rule off` to choose a cut. With `--baseline`, the report also gives the p value of an exact two-sided sign test of the helped and the harmed cases (`sign test`), and the paired 95% interval of the change of the log probability. The unchanged cases do not count. For example, 1 helped and 7 harmed cases give p = 0.070, which is not significant at 5 percent. The median time and the warm time also show the 95th percentile (p95) and the most time (max). `--screen on|off`, `--clipboard on|off` and `--history on|off` turn the screen text, the clipboard and the earlier writing on or off in the settings, as the switches of the app do (default: on). With an off value, the prompt has no such section, and the `words` of a case give no word bias. To measure the gain of one section, run the same cases with that switch off, and compare the run with the run with all on (`--baseline`). `cases/chat.jsonl` has one or two characters in chats, emails and documents. Run it also with `--notes`. `cases/new_line.jsonl` has cases that end with Enter (a case with a line break at the end of `before`, or with `before_enter`). Run it with `--name "Sara Novak"`. `cases/mid_line.jsonl` has cases with text after the caret on its line. There `next` is all the text up to that text, and each word of a suggestion after `next` is wrong. Run it for a change to the text after the caret or to the filters of a suggestion. On `cases/typos.jsonl`, a case matches when no suggestion finishes the word with the typo. Each typo case has `fixed`, the text before the caret without the typo, and the report counts the fixes that write the meant word (`typo fixes`) and the fixes of words without a typo (`other fixes`). A change to the prompt or to the context must show a gain here before it ships. `cases/left_out.jsonl` has cases from the stores of the writers, each with one text of its store left out of the history (`left_out`). Run it with each `--word-choice` for a change to the word bias, and compare it with the run with `--word-choice off`. The `shared` group of the stores files has cases where the next word comes from another app (`help`), where another app pushes a wrong word (`harm`), and where the place and another app give different next words (`priority`). Run them with `--word-choice medium` for a change to the scope of the history. `cases/repeats.jsonl` has the stores `writers/NAME_repeats.jsonl`, where the writer sent 3 messages 3 or 4 times, and one of them one more time with a typo. Run it with `--word-choice medium` and `off` for a change to the examples or to the word bias. `--prompts FILE` writes the prompt of each case. Use it to read the examples of a case.
- First key: `cargo run --release -p typealike_llm --features vulkan,cuda --example first_key -- MODEL.gguf --backend vulkan`. It loads the model 6 times (`--loads N`), and times the first completion after each load, a later key, and a whole other prompt after the first completion. The first request of a load goes with the load request (no warm-up) or after the answer of the load (with the warm-up), in turns. `--first queued|after-load` sets the way of the first load, which also starts the backend as at the start of the app. Run it several times with each value. The NVIDIA Vulkan driver keeps the compiled shaders for each program, so the first run of a new build compiles them for some seconds. Close TypeAlike before a run.
- Settings file: `%LOCALAPPDATA%\TypeAlike\settings.json` on Windows, `~/Library/Application Support/TypeAlike/settings.json` on macOS (the General, Apps and websites, Screen text, Personalization and Energy saving panes write it through `typealike_settings::SettingsFile`).
- Log file: `TypeAlike.log` in the temp folder (`%TEMP%` on Windows, `$TMPDIR` on macOS), next to the terminal output. Each start adds to it, so the log of a crash stays. A start moves a log above 10 MB to `TypeAlike.previous.log`. `TYPEALIKE_LOG` sets the levels in the syntax of `tracing_subscriber::filter::Targets` (default `info`), for example `debug` or `info,typealike_llm=debug`. The llama.cpp logs have the target `llama-cpp-2`. A panic also goes to the log. The first line of each start gives the version and the GPU features of the build. `docs/logging.md` tells how to read the log and gives the rules for new log lines.- Earlier writing: `history.bin` in the folder of `settings.json`, only while "Use earlier writing" is on. It is sealed with ChaCha20-Poly1305. The key is a generic password in the login keychain on macOS (service `io.github.israperez98.typealike`, account `history-key`), and `history.key` (locked with DPAPI) next to `history.bin` on Windows. To delete both resets the history.
- Windows autostart: the General pane writes the `TypeAlike` value in `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`. It starts the program that wrote it. To turn it on also removes the `TypeAlike` value in `...\Explorer\StartupApproved\Run`, so a stop from Task Manager does not stay (`typealike_windows::StartupEntry`).
- macOS autostart: the General pane writes the launchd agent `~/Library/LaunchAgents/io.github.israperez98.typealike.plist` (`typealike_macos::LaunchAgent`). It starts the program that wrote it.

## Layout
Virtual workspace, flat `crates/`. A module with children is `foo.rs` plus `foo/` (never `mod.rs`, clippy `mod_module_files`). A large module is a facade: its children are private and it re-exports their items with explicit `pub use`, so each item keeps one path. `settings_window` is different: it only groups the public pane modules and `view`. A large unit test suite is in `foo/tests.rs` (groups in `foo/tests/`). The tests of several core modules share `test_support.rs`. `history` and the llm `worker` have their own `test_support.rs`.
- `typealike_core`: engine, matching, accept state machine, prompt (in the first person: a fixed frame that the user cannot edit, the notes about the writer from the General pane (a default text in the first person when the settings file has no notes), the name of the writer, place line, text around the caret, clipboard, screen text, a budget of estimated tokens for each section, and a heading just before the text before the caret), the format of known apps and web pages (`place`), the screen text that the prompt keeps (`screen`: noise, the times of chat headers, distance to the caret, budget, the lines above and below the caret. The lines below come first, then the lines above. The text after the caret comes last, next to the heading, so that the model writes text that leads into it), the earlier writing of the user (`history`: the texts of finished sessions without their secrets and without the text that the user did not write. The place of a text is its web page in any browser, else its app. Each app of the Personalization pane has a scope: Off, Only this app or All apps. A session uses only the texts of its pool: the texts of its own app with "Only this app", else the texts of all the apps with "All apps". A text never replaces or continues a text of another pool. A text that the user typed in full is a new text, also when an older text is the same, so a repeated message counts each time. The store keeps at most 1,000,000 characters of text and at most 10,000 texts. Above either limit, the oldest texts of the store go, in any place. The examples of the prompt (the texts of the same place that match the topic of the field: one on the CPU, two on a GPU. In a place with at most 3 texts, its newest texts fill up to two examples. The texts of other places of the pool that share at least 3 topic words with the field fill the free examples. A place without texts gets the newest text of another place with the same format. Among texts that match the same, the text with more copies in its place comes first. A near copy of a picked example is no example: two texts that differ in at most 2 inserted, deleted or changed characters, or in at most 10 percent of the characters of the shorter text. Thus the spelling that the writer uses most stays), the word bias of each pool with its spelling, the phrases that the writer repeats (when the word choice is on, a word that came after the same 3 words at least 3 times, and in at least 60 percent of the times, shows without the model while the line after the caret is empty), the next-word bias (at most 8 words that came after the last 3 words before the caret, else the last 2, each with the strength times its share. The runs that came only one time are left out). The phrases and the next words come from the texts of the place when these texts have the last words, else from all the texts of the pool. The core also has the `WritingHistory` and `KeyVault` traits), settings model, Models, Playground, General, Apps and websites, Screen text, Personalization and Energy saving panes. The Energy saving pane (`EnergySavingPane`) has the idle timeout (off, 15, 30 or 60 minutes, 30 by default), the switch "Stop in energy saver" (on by default) and the switch "Stop during games" (on by default). Each key or click starts the idle timeout again (`Timer::Idle`). When it runs out, the session ends and the suggestion model unloads. The next request for a suggestion first loads the model again (`App::end_stops_before_request`), and the runner completes the request after the load. While the energy saver of the computer is on (`EnergySaver`: energy saver or battery saver on Windows, Low Power Mode on macOS) and the switch is on, suggestions stop as in a pause: no request, no prepare, no screen read and no phrase. The model unloads, and the badge and the tray show "TypeAlike (off to save energy)". The platform gives the state at start (`Startup`) and each change (`Controller::on_energy_saver`). When the energy saver goes off, the model loads again, unless the idle timeout ran out. While a game is in front (`GameActivity`) and the switch "Stop during games" is on, suggestions stop as in the energy saver, the model unloads, and the badge and the tray show "TypeAlike (off during a game)". The platform gives each change of the app in front (`Controller::on_game`). After the game, the model stays unloaded until the next request for a suggestion, as after the idle timeout. Thus a quick switch out of a game does not load the model. `App::stop_reason` gives the reason for an unloaded model (pause, energy saver, game, idle, in this order), and the model menu of the General and Playground panes tells it. The Apps and websites pane (`SuggestionPlaces`) has a switch for each app and for each website (host) where a suggestion showed. TypeAlike adds each place with its switch on when its first ghost text shows on the screen (`Desktop::is_ghost_shown`). The Screen text and Personalization panes add the app at the same time. Thus a window without a text field, such as a game, never goes into these lists. A website matches only its exact host. A field whose app or website is off works as a paused field: a key gets no request, no ghost text and no phrase, and Tab goes to the app. The settled input reads no screen and prepares no prompt there. Without a session, only a key that types or deletes a character reads the field, one time. The badge there shows as paused ("TypeAlike (off here)"). A session in a place that the user turns off ends, and the earlier writing keeps none of its text. The pause keeps that text. The Screen text and Personalization panes dim the row of an app whose suggestions are off. A field whose role marks it as a search box (`Surroundings::is_search_field`) gets no suggestions, as the address and subject fields of an email. The platform reads the role, never the labels, so the rule works in any language. Core gives the set of line breaks (`desktop::is_line_break`) that the platforms use. The suggestion lengths go from very short (3 tokens) to very long (22 tokens), with medium (10 tokens) as the default. Each length also gives the cut of the tail of its requests: about 2 percent up to medium, and a lower cut for long and very long, so that each token can be as unsure as at medium. On the CPU backend, the General pane offers only very short and short, and a longer saved length works as short. The badge at the caret opens a menu (`BadgeMenu`): pause or resume, the suggestion switches of the app and of the website where the user types ("Show suggestions in <app>", "Show suggestions on <host>"), the screen text switch of the app, and the scope of its earlier writing (Off, Only this app, All apps). An entry is dimmed while the main switch of its pane is off. The screen text switch and the scope are also dimmed while suggestions are off in that app or on that website. The suggestion switches stay enabled. A pick changes the settings as the pane does. The rule for typos (the General pane, on by default) gives each request a minimum for the typed letters of the last word (`TypoRule::typed_letters_cut`, sent as `TypoCheck`). With "Fix typos" (on by default, shown while the rule is on), the request also asks for a fix. A completion with a `Correction` shows the typed letters struck through and the fixed word after the caret (`Reaction::ShowFix`, `Ghost::Fix`), and Tab deletes the typed letters and types the fixed word (`Reaction::Replace`). A space or one of `, ; : ! ?` after the typed letters keeps the fix, with at most one sign and then one space (`fix_after_delimiter`). The typo and the fixed word then end with that space or sign. Thus the red line goes through it, and Tab deletes it and types it again after the fixed word. The rest of the suggestion keeps its text after that space or sign, and a rest that does not start with it goes. Another key asks again. At Tab on such a fix, core reads the field. When the text before the caret does not end with the typo, the app changed the word (an autocorrect). Then Tab replaces nothing (`Reaction::Swallow`) and the session ends. A read that ends with less of the space or the sign, or no field text, allows the replace. Tab types the next part of a suggestion: the next word with the whitespace before it. The closing punctuation, quotes and brackets at the end of a word (`CLOSING_SIGNS`) are not a part of that word. The next Tab types them alone, also after a fix ("Best| regards, Sam" takes " regards", then ",", then " Sam"). A word of only signs is one part. Tab takes a suggestion only while the ghost text shows on the screen (`Desktop::is_ghost_shown`). After a Tab, the rest of the suggestion also counts as shown while it waits for the caret, so that a quick Tab types its next part. After the last part, core asks for the next suggestion as after a typed key (`AfterAccept::Next`). When the completion still runs, core asks when that completion ends without more text. Until the next suggestion shows, a quick Tab does not reach the app while a suggestion can still come (`TabHold`, at most 800 ms): after a request, a shown phrase or a completion that still runs (`App::has_offer`). Core swallows that Tab and keeps the session. The held Tab does not take the next suggestion, because Tab types only text that the user saw. A Tab while the next ghost text shows, any other key, a click, a focus change, a pause and a completion without a suggestion end the hold. While a completion runs, a typed key that continues the text that the completion added so far keeps its request, also when that text does not show yet. This does not occur when the earlier writing gives a phrase or next words for the new text. When the completion then gives no ghost text after the typed text, core asks again as after a typed key. Each session keeps the last 16 suggestions that the ghost text showed, each with its text before the caret (`ShownSuggestions`). When the text before the caret is such a text and then a start of its suggestion that is shorter than the suggestion, core shows the rest at once, with no request. Thus a backspace back to a place where a suggestion showed, or a retype of the suggested letters after a wrong letter, needs no model. Only the text of a completion goes into this memory, never a fix or a phrase. An earlier suggestion comes before a phrase. After a key, the ghost text shows only at a caret that moved, because a terminal moves its caret only after the program in it writes the text back. A shell that reads the caret off its thread (`CaretLook::Later`, Windows) gives each read (`CaretRead`: the caret and the frame of the focused field) to `Controller::on_caret_read`. A shell that reads the caret at once (`CaretLook::Now`, macOS) gives the read as its answer. Core compares the caret with the caret of the last look that found a caret that moved, and a caret that did not move gets only the badge. A caret more than 4 caret heights outside the frame of its field counts as no caret, and core hides the ghost text and the badge. While the badge shows, a scroll (`Controller::on_scroll`) hides the ghost text and the badge, and keeps the suggestion. They show again at the caret 40 ms after the last scroll event (`CARET_SETTLE_DELAY`). The look at the caret that waits ends, because its caret can be stale. A scroll does not change the text, so the ghost text also shows again at a caret that did not move. A scroll does not end the session, starts no input settle and reads no screen. The fix of a typo of the same length does not move the caret, so the rest after it shows at once. The ghost text and the badge show 40 ms after a key (`CARET_SETTLE_DELAY`), at the caret that the key moved. A suggestion that comes after this wait shows at once (`GhostTiming::Now`). While the ghost text does not show, core looks at the caret again every 20 ms, at most 20 times, and then shows the ghost text at the caret where it is. Each ghost text goes to the platform with its placement (`GhostView`). The ghost text after the caret has the color of the field text (`TextColor`) at the opacity `GHOST_TEXT_ALPHA` (half), as a placeholder. Light text (`TextColor::is_light`: more contrast with black than with white) gets the colors of a fix for a dark background. When the platform finds no caret, it can show the ghost text in the mirror next to the focused field. The mirror (also the card below the caret) shows the end of the typed word before the ghost text (`GhostView::typed_word`: the text after the last space, at most 24 characters, without the typo of a fix). The typed word has the primary text color and a semibold font. The ghost text has a lighter color with a contrast of at least 4.5:1. When text follows the caret on its line, the ghost text goes below the caret (`GhostPlacement::BelowCaret`), because at the caret it would cover that text. The ghost text after the caret keeps only the whole Tab parts that fit before the right edge of the frame of its field, less 4 px (`FIELD_EDGE_GAP`, `GhostView::fit_to`). The platform measures each cut in the font of its overlay (`Shell::ghost_width`). When not even the first part fits (for a fix, the fixed word), the whole ghost text goes below the caret. Without a frame with an area, the ghost text stays whole. The session keeps the whole suggestion, so each Tab shows the next parts at the new caret. After a Tab, a rest whose start did not show does not count as shown: a quick Tab then waits in the Tab hold until the rest shows. A suggestion also stops where it writes the text of that line again (`SHARED_UNITS`: from a word, or from the closing punctuation that starts that line, the words agree in at least 2 words and signs in a row, or up to the end of the shorter). Each suggestion of the model also stops before its first word that the dictionary of the OS (`SpellChecker`, a service of the bin) does not know, unless the prompt, the text after the caret or the word bias of the pool holds that word in any case (`engine/spelling.rs`). A word with fewer than 3 letters, a digit or a sign inside, or a capital letter inside (code) needs no dictionary. The first word counts with the typed letters before it, so an unknown first word hides the suggestion. The engine keeps each answer of the dictionary, because each answer costs a call to the OS. The phrases of the earlier writing and the shown suggestions need no dictionary. `spelling::dictionary_languages` gives the dictionary of each preferred language of the user. A request inside a line has no cut of the tail and twice the tokens (`INSIDE_LINE_TOKEN_FACTOR`), because the end that fits the text after the caret ends the suggestion, and a sentence that the writer inserts can then finish. A field that hides the text of that line (`Surroundings::is_caret_line_hidden`: the input box of a terminal of xterm.js) always gets the ghost text below the caret, and no phrases. With the default preparation (at the first key), TypeAlike still prepares the prompt when the input settles in a place where the earlier writing has a text. A session lasts while the user types in the same field. Core reads each no-break space of the field text (U+00A0, U+202F, U+2007) as a plain space (`excerpt::plain_spaces`), because a web editor shows a typed space at the end of a text as a no-break space. Without this, the typo rule and the token healing take the space as a part of the last word. After Enter, core reads the field again when the input settles or at the next key. When the field shows the text of the session (or the field text that core read at Enter, because a dead key or an autocorrect can change the typed text), line breaks, and then no letters, the session continues on the new line, and the settle asks the model for a suggestion there. Else the session ends. A dead key (`Key::Dead`) does not end the session. When the input settles without Enter, core reads the field again (`Engine::follow_field`). When the field shows the text that the user typed since the last read, or that text with the same words, each with at most 2 changed characters, the same word at the caret and the same last character, the session takes the text of the field. The word at the caret of a read counts as typed, because the app changes a word when the user finishes it. Thus an autocorrect of the app goes into the prompt and into the earlier writing. A click and a focus change still end the session. A screen read starts at the first key of a session and when the input settles, unless the session has its final screen text. A session first uses the stored screen text. The answer of its own read replaces that text one time, when the text changed. When the read of the accessibility tree gives no lines and the platform can do an OCR, core asks for an OCR read. The level of the Screen text pane (fast or accurate) shows only when the OCR of the platform has levels (`OcrLevels`). The `Controller` runs TypeAlike from the platform events (keys, clicks, timers, tray, settings window, service answers). Pure Rust, no OS. Each platform implements the `Shell` trait: it reads the desktop (`Desktop`) and does the OS effects that the controller asks for. The platform runtimes only translate OS events into controller calls. Core also holds the key-press rules (`Key::from_press`) and the badge click rule (`BadgeClickFilter`). Escape always counts, Tab only without a modifier, and Enter and Backspace only alone or with Shift. Any other key with a shortcut gives `Key::Other`. Else a key gives the typed character, a dead key, or `Key::Other` when it types no single character. Each platform maps its key codes and modifiers to the neutral kinds of `key`. Each pane (`settings_window`) gives its page of the settings window as a tree of sections and rows (`settings_window::view`), with a stable id for each control. Each row of a setting also has a picture before its label (`RowIcon`). Each platform has one renderer for each kind of row and sends back what the user did with a control, so a new setting needs no platform code.
- `typealike_windows`: hooks, overlay, badge at the caret, `SendInput`, tray (Win32, main thread). A fix shows a red line through the typed letters, as wide as the letters in the font of the overlay, and the fixed word in green (Fluent colors, or the colors of high contrast). Without the color of the field text (also in a terminal of xterm.js), the ghost text after the caret is a neutral gray (`NEUTRAL_GRAY`, the same in light and dark mode, so it shows on a light and on a dark background). In high contrast, it is `COLOR_GRAYTEXT`. When text follows the caret on its line, the overlay shows the typed word and the ghost text on a card below the line of the caret, with the ghost text under the caret, or above the line at the bottom of the work area. The card has the fill and the border of the Fluent tooltip, as the badge. The typed word and the typo of a fix are in the Fluent primary text color and semibold. The ghost text is in the Fluent secondary text color in light mode and the tertiary one in dark mode (`CardText`). In high contrast, they are `COLOR_WINDOWTEXT` and `COLOR_GRAYTEXT`. A replacement sends a Backspace key for each deleted character before the text. The shell queues each replacement, and each inject message types the oldest one. The mouse hook gives `WM_MOUSEWHEEL` and `WM_MOUSEHWHEEL` to `Controller::on_scroll`. Caret reader on its own thread: the system caret, else the caret object of the focused window (`OBJID_CARET` of Microsoft Active Accessibility: Chromium browsers and Electron apps such as VS Code), else UI Automation (UIA) for apps that draw their own caret (WinUI). Each read of the caret also gives the frame of the focused field: the UIA `CurrentBoundingRectangle` of the focused element when it has an area, else the `GetWindowRect` of the focused window. The runtime gives the answer to the newest read to the controller, and the shell draws at the caret of that answer (`NewestCaret`). A UIA caret with a value that is not finite counts as no caret. The UIA caret is the right edge of the character before it. At the start of the field or after a line break, it is the left edge of the character after it, else the left edge of its line (`ExpandToEnclosingUnit` with `TextUnit_Line`), else no caret. A line that starts before the caret is the line above, and the caret is one line lower. A caret shorter than a line of text does not count, because Qt apps such as Telegram keep a transparent 2 x 2 px system caret for input methods. In a terminal of xterm.js (the class `xterm-helper-textarea` in UIA), the caret moves up to the row of the terminal screen that holds the hidden input box, because VS Code draws that box below the top of its row. Each caret has the color and the font face of the text before it (UIA `ForegroundColor` and `FontName`), but not in a terminal of xterm.js, and not when that color is the `BackgroundColor`: Chromium drops the alpha of the transparent text of a hidden input box. A system caret keeps the face of `WM_GETFONT` and takes the UIA face only when the window gives none. The overlay draws in that face when it is installed, else in Segoe UI, always at the height of the caret. It also reads the text around the caret (UIA `TextPattern`, else a classic edit control), the field labels (UIA `LabeledBy`, `Name`, then `HelpText`, else `FullDescription`) and the host of the web page (the URL in the value of the nearest Chromium or Gecko document) 40 ms after each key, click and focus move. The shell keeps that read for the hook, because the hook must not wait for UIA. A field that UIA marks as a password field (`IsPassword`) gets no suggestions. A field with the ARIA role `searchbox` (UIA `AriaRole`: a web search box or an HTML `<input type="search">`) is a search field. A native search box gives no ARIA role. After a click or a focus move, the field also counts as a password field until a read of the new field tells that it shows its text. A read that gives no focused element (`FieldAnswer::Unknown`: the request failed or did not finish in time) does not change whether the field counts as a password field. The caret reader waits at most 500 ms for an element and 3 s for each request about an element (`Uia::limit_waits`), so that one app that does not answer cannot stop the reads in all apps. Screen text reader on its own thread with a low priority: the UIA text elements of the foreground window, else the OCR of a band of the window around the field (`Windows.Graphics.Capture` and `Windows.Media.Ocr`). The OCR needs Windows 11, because Windows 10 draws a border around the window at each capture. It stops while energy saver is on. A watch of the energy saver (`EnergySaverWatch`: `PowerManager::EnergySaverStatusChanged`) sends each change to the main thread. A game watch on its own thread with a message loop (`GameWatch`) sends whether the app in front is a game: a program in the game list of Windows (`HKCU\System\GameConfigStore\Children`, each entry of the kind 1 with its `MatchedExeFullPath`). Game Bar and Game Mode keep this list, which is not a documented API. A WinEvent hook (`EVENT_SYSTEM_FOREGROUND`) tells the thread each change of the foreground window, and a registry notification each change of the list. Settings window (WinUI 3 through windows-reactor, on its own UI thread), as the Settings app: a color icon of the Fluent UI System Icons for each page in the navigation (`assets/fluent`, the page symbol in high contrast), and a glyph of the icon font at the leading edge of each card of a setting. The physical cores of the CPU and their efficiency classes (`cpu_cores`). The spelling dictionaries (`SpellingDictionary`): an `ISpellChecker` for each language of `GlobalizationPreferences::Languages`, on the main thread in the multithreaded COM apartment. All FFI.

Each look at the caret also gives the frame of the focused field. A field whose app does not answer the read of its subrole in time (0.1 s, `kAXErrorCannotComplete`) counts as a password field. A field with the subrole `AXSearchField` (a native search field or an HTML search box) is a search field. The address bar of Chrome gives no subrole. The caret is the right edge of the character before it (`AXBoundsForRange`). At the start of the text or after a line break, the caret is the left edge of its line, with the top and the height of that line (`AXLineForIndex`, `AXRangeForLine`, then `AXBoundsForRange` of the line). A line that starts before the caret is the line above, and the caret is one line lower. When the line of the caret is empty, as after the last line break in TextEdit, the line of the character before the caret gives the box. When that read gives no box, as in a contenteditable field of Chromium, the caret is the box of the selection as a text marker range (`AXSelectedTextMarkerRange`, `AXBoundsForTextMarkerRange`). A selection box that is the frame of the field gives no caret, because Chromium gives that frame for a field without laid-out text (the editor of VS Code). A caret box needs a height above 0 and finite edges, and the frame of a field needs finite edges. - `typealike_llm`: runs GGUF models with llama.cpp (`llama-cpp-2`) on one worker thread (`ModelRunner`), on the backend that each load names (CPU, Vulkan, CUDA, Metal). macOS always loads on Metal. On the CPU, a prompt runs one thread on each performance core of the `CpuCores` that the bin gives (at least 4 threads when the CPU has 4 cores), and each added token runs on at most 4 threads. Without `CpuCores` (macOS, tests, eval), and on the GPU backends, llama.cpp keeps its threads. Refuses a GPU load when the whole model does not fit in free GPU memory. On Vulkan, CUDA and Metal, each load warms up the backend before it answers (`WarmUp`): it makes the context, decodes a prompt of one batch and one added token, and then forgets them. Thus the first completion after a load does not prepare the kernels and the memory of the GPU. A request that waits stops the warm-up. The CPU does no warm-up, because it costs more CPU time than it saves. When llama.cpp starts, it logs each device that llama.cpp found, because a release build of llama.cpp loads its GPU backends without a log. Heals the last word of each prompt (token healing), but never takes back a line break. Adds the next-word bias only to the first token that it adds. It finds the tokens that agree with the healed text in a sorted table of the token texts, which it makes at each load. Gives the log probability of each added word (at a healing step, the share of the token among the tokens that agree). Gives the log probability of the typed letters of the last word: the higher of the healing path and the tokens that cover the letters at the first healing step (`TypedLetters`), because the healing path can go through a lone space. It adds no text when the letters are less likely than the minimum of the request. When the request asks for fixes, it looks among the 64 most likely tokens at the start of the word for one that fixes the letters with one edit (a swap of two letters, a changed, an extra or a missing letter: `correction`). The fix keeps at least 3 letters and is not a typo itself. Then the completion starts again from the fixed letters with that token, and sends no parts. After the first word, it stops when the added text gets less likely than the cut of the request, and leaves out the word of that token. When the request asks for it (`SentenceEnd::Stop`: the switch "Stop at the end of a sentence" of the General pane, on by default, just below the suggestion length. While it is off, a warning below it (`NoteTone::Warning`: a warning sign, yellow text on macOS) tells that suggestions are often wrong after the first sentence), it stops before a new word after the end of a sentence: a period, "!", "?", "…" or the CJK signs 。！？, also before closing quotes and brackets. Without that stop, the cut of the tail applies to each sentence on its own, and after the end of a sentence that it added, it takes the most likely token that keeps the text on its line (among the 64 most likely: not a line break, the end of the text or markup), because the model often ends the message there. A period ends a sentence only after a word of at least 2 letters, because one letter is often an initial or the end of "e.g." or "a.m.". The word must also not be one of the English and Spanish `ABBREVIATIONS`, such as "Mrs.", "Sra." or "pág.". At the token limit, it leaves out the last word, unless that word ends a sentence or it is the only word. With text after the caret on its line (`line_after` of the request), each step also reads how likely the model finds the start of that line next (the tokens that agree with it, without the tokens of only whitespace, because Gemma writes a lone space before digits). The added text ends where the model finds the added text and then that line most likely, and the completion stops when the model starts to write that line. The parts show only up to that end. Before that line, a token that opens a placeholder (an opening square bracket before a letter or a digit) also stops the completion, because the ghost text ends before a placeholder. Keeps the last prompt in the llama.cpp cache, so the next prompt decodes only the tokens that it adds. It decodes the new tokens of a prompt in batches of at most 256 tokens on Vulkan, CUDA and Metal, and 128 tokens on the CPU. A newer request stops the decode between two batches. For a recurrent model (Qwen3.5), it also saves the state before each of the last words, so a backspace across a word does not decode the full prompt again. Sends the text of a completion while it grows. A drop of `LlamaCpp` waits until the worker frees the model, because on Metal llama.cpp stops the process with an assert when the process exits with a loaded model (macOS quits through `exit`). With the "Show words early" setting, the engine shows its complete words at once. Build needs CMake and libclang.
